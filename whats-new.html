VonCMS v1.27.6 "OverDrive"

Original notes

VonCMS v1.27.6 combines the unreleased v1.27.5 development work with the final v1.27.6 security and stability hardening.

This release improves article sharing, editor links, public search, contact-form protection, SEO redirects, installer safety, SMTP security, view counting, password recovery, proxy handling, and automated regression coverage.

Content and Publishing

  • Added Copy Link and supported-device native sharing to public article controls.
  • Retained Facebook, X, WhatsApp, LinkedIn, Telegram, and email sharing.
  • Removed unnecessary query strings and fragments from shared URLs.
  • Added Normal, Sponsored, Nofollow, and UGC options for individual editor links.
  • Preserved supported link relationships after save, preview, reload, public rendering, and no-JavaScript output.
  • Improved multi-word public search so every normalized search term is required.
  • Retained prefix matching while visitors type.
  • Kept API, server-rendered, paginated, and hydrated search results aligned.

SEO and Redirects

  • Added automatic permanent redirects when published post slugs change.
  • Added the same redirect protection for published page slug changes.
  • Covered category, date-based, root-domain, and subfolder permalink formats.
  • Prevented redirects from being created for Draft or Archived content.
  • Preserved existing Redirect Manager rules and blocked conflicting replacements.
  • Avoided unnecessary redirect rules for plain ID permalink formats.

Contact Form Protection

  • Replaced the predictable static contact-form honeypot with a session-bound random trap field.
  • Added an HMAC-signed timing challenge.
  • Rejects malformed, tampered, expired, replayed, cross-form, and unrealistically fast submissions.
  • Uses the existing fake-success response for detected bots.
  • Consumes a valid challenge only after successful mail delivery.
  • Preserves CSRF protection, rate limiting, accessibility, validation, SMTP, and root or subfolder routing.
  • Requires no database migration or third-party anti-bot service.

Installer Security

  • Added a server-generated one-time setup key for fresh installations.
  • Database initialization and administrator creation require the correct setup key.
  • Added a non-blocking exclusive lock so two requests cannot claim the same installation concurrently.
  • Keeps administrator and default-setting creation transactional until configuration activation succeeds.
  • Writes configuration and completion-lock files through same-directory temporary files before atomic activation.
  • Failed installations retain a safe retry path without creating duplicate owner data.
  • Successful installation consumes the setup key.
  • Existing von_config.php and install.lock files continue to block reinstallation.

SMTP Security

  • Authenticated SMTP now requires TLS or SSL.
  • The legacy unencrypted none mode is rejected before any network connection or credential command.
  • General Settings rejects new plaintext authenticated SMTP configurations.
  • Existing legacy plaintext settings are clearly marked for repair.
  • TLS, STARTTLS, implicit SSL, and PHP mail fallback remain supported.

Public View Protection

  • Added short-window session-based deduplication for post and page views.
  • Repeated valid POST requests from the same visitor session no longer inflate view totals.
  • Does not add database writes solely for throttling.
  • Does not group unrelated visitors behind the same CDN or proxy IP address.
  • Only published or legacy-public content can increment.
  • Failed updates release their claim for a safe retry.
  • View updates do not modify the content edit timestamp.
  • Analytics identity and consent controls remain unchanged.

Password Recovery

  • Password reset now locks the matching valid token inside a database transaction.
  • Password updates require the exact token to remain valid at update time.
  • Exactly one affected user row is required before success is returned.
  • Reset tokens become strictly one-time even under concurrent requests.
  • Remembered login tokens are revoked inside the same transaction.
  • Existing password rules, expiry handling, and public enumeration-safe responses remain unchanged.

Proxy and Rate-Limit Hardening

  • Forwarded HTTPS headers are accepted only from loopback or explicitly configured trusted proxy IP and CIDR entries.
  • Public clients cannot mark an ordinary request as HTTPS by spoofing forwarded headers.
  • Direct HTTPS and legitimate reverse-proxy or CDN configurations remain supported.
  • Rate-limit storage failures retain availability-preserving fail-open behavior.
  • Storage failures now produce bounded server diagnostics and a Primary Admin system alert instead of failing silently.

Regression and Security Coverage

  • Added executable coverage for installer ownership and concurrent setup claims.
  • Added runtime checks for encrypted SMTP authentication.
  • Added repeated-view deduplication tests.
  • Added atomic password-reset token tests.
  • Expanded article-sharing tests for canonical URLs, malformed input, Unicode, subfolders, clipboard fallback, native sharing, private content, and all bundled themes.
  • Re-audited authentication, CSRF, uploads, redirects, path handling, proxy behavior, direct helper access, and sensitive storage boundaries.
  • No additional reproducible SQL injection, authentication bypass, unsafe upload, path traversal, SSRF, unsafe deserialization, open redirect, or private-storage exposure was found in the reviewed paths.

Dependencies

  • Updated compatible dependencies inherited from the v1.27.5 development cycle.
  • Verified all direct dependencies against the current npm registry.
  • npm outdated reports no pending updates.
  • npm audit reports zero known vulnerabilities.

Updating

Back up your website files and database before updating.

Existing installations may update using the VonCMS updater or upload the latest Deploy package manually.

No new schema migration is required for this release. After updating, verify:

  • Homepage
  • One article
  • One page
  • Admin dashboard
  • Database Status

Run Database Repair only if Database Status reports schema drift.
