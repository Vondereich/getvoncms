VonCMS v1.26.11 - After Hours

VonCMS v1.26.11 closes the current After Hours release cycle with a canonical first-publication timestamp, explicit and data-preserving database repair, cleaner public discovery, safer admin mutations, and final compatible dependency maintenance.

This release also includes the v1.26.10 canary baseline that was tested in development but not published as a separate GitHub release.

Highlights

  • Added published_at to posts and pages so creation time, first publication time, scheduled time, and edit time remain separate.
  • Kept first-publication dates stable when published content returns to Draft or Archived and is published again.
  • Aligned public APIs, SSR hydration, visible dates, ordering, schema, RSS, llms.txt, Related Posts, and sidebar freshness to one publication-time resolver.
  • Moved permanent schema creation and alteration out of ordinary public and authentication traffic.
  • Added explicit Primary Admin Database Repair with exact schema ownership, advisory locking, safe preflights, resumable operations, and controlled stops for unsafe populated drift.
  • Kept the database status check read-only and added a short healthy-result reuse window for lighter admin navigation.
  • Improved RSS reader interoperability, Gallery file-size accuracy, crawlable public links, maintenance boundaries, plugin delegation, embedded-video fullscreen support, and canonical admin mutation responses.
  • Updated compatible dependencies, including @openrouter/sdk 1.2.81, react-router 8.3.1, TipTap 3.30.5, lucide-react 1.35.0, @vitejs/plugin-react 6.1.1, and @types/node 26.4.0.

Included v1.26.10 Canary Baseline

  • RSS Atom self references now match the clean feed alias, while feed output removes unsafe inline styles and embedded elements for conservative readers.
  • Gallery lightbox metadata reuses the media API file-size value without double conversion.
  • Public account, 404 Home, and valid Holiday Gift Widget destinations use safe anchors with SPA and subfolder behavior preserved.
  • Admin user and comment mutations are idempotent, serialized, method-checked, and based on canonical server state.
  • Homepage and post hydration share one content source with the no-JavaScript fallback, while explicit runtime schema ownership keeps DDL out of ordinary traffic.
  • Database Repair is resumable and data-preserving across owned columns, indexes, foreign keys, optional tables, and compatibility stops; unsafe populated drift stops for operator review.
  • Database status remains read-only, missing optional storage fails safely, and bounded status reuse avoids repeated metadata scans during rapid admin navigation.
  • Appointed admins can manage ordinary plugin activation without receiving primary-admin access to credentials, custom code, analytics ownership, or media storage.
  • Nginx VPS guidance, maintenance mode failure boundaries, and embedded-video fullscreen persistence are aligned with the shared-hosting runtime.

Existing Site Upgrade

  1. Back up the website files and database.
  2. Update through Dashboard OTA or upload the complete v1.26.11 Deploy ZIP.
  3. Sign in as the Primary Admin.
  4. Open Settings > Tools > Repair Database and run it once.
  5. Review the repair result and confirm Database schema is healthy.
  6. Verify the homepage, one post, one page, login, and the admin dashboard.

Fresh installations already create the current schema and do not need this upgrade repair.

Database Repair is separate from System Tools > Repair `.htaccess`. OTA protects the live .htaccess. Manual Deploy ZIP users must preserve their live .htaccess; the dedicated .htaccess repair remains the earlier one-time v1.25.0 managed-block migration step.
