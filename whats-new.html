VonCMS v1.28.0 - The BluePrint

The BluePrint begins the VonCMS 1.28.x series, building on the closed 1.27.12 "OverDrive" maintenance line. This release brings a private Editorial Calendar, grouped admin navigation, optional browser-based analytics and encrypted owner AI credentials, alongside publishing, import and maintenance improvements.

VonCMS remains self-hosted PHP + React. Production hosting does not require Node.js, npm or Composer.

Editorial Calendar and admin navigation

  • A private Month / Agenda calendar with date, type and content-author filters, desktop details and responsive drawers.
  • Authorized Admins and Moderators can manage internal events with plain-text notes, inclusive all-day dates, version-conflict checks and transactional audit records.
  • Existing Post/Page publication entries appear as read-only projections. Viewing Calendar does not reschedule or republish content.
  • New events use current or future dates; historical entries remain available for review. There are no public calendars, recurring events, reminders or external calendar sync in this release.
  • Dashboard stays first, followed by Create and the grouped Content, Extensions and Monitoring menus. Role-aware shortcuts open the correct Post, Page or Event workflow, and active groups can be collapsed without leaving the page.

VonAnalytics: Strict and Balanced

  • Strict remains the default: IP-based measurement with a 30-minute recorded-visit window.
  • Balanced is optional: an installation-scoped, first-party browser identifier distinguishes browsers sharing an IP, with a 30-day identifier lifetime and sessions ending after 30 minutes of inactivity.
  • Existing plugin and consent settings govern collection. Browser identifiers are separate from authentication, and stored visitor identities are hashed.
  • Reports keep measurement modes separate. Clearer period totals, daily chart labels and tooltips explain why adding daily unique counts does not equal the period-wide unique count.
  • Trusted-proxy configuration and bounded tracking admission improve deployment handling. Counts remain visitor estimates, not verified people or fraud-resistant accounting.

Protected owner AI credentials

  • The shared Gemini API key supports authenticated encryption with a separate private installation key; Settings responses show masked status rather than key contents.
  • Primary Admin can Rotate Encryption Key without deleting files or re-entering the saved provider key. Rotation preserves the selected model and existing local expiry.
  • An explicit owner Settings save migrates a legacy plaintext key. Missing or corrupt encryption material does not silently fall back to plaintext or regenerate during a read.
  • Accepted API Settings saves synchronize editor AI readiness without requiring a reload. Gemini model choices and privacy guidance are updated; eligible requests opt out of optional provider storage without overriding provider-required retention terms.

This is protection for the existing shared owner credential. Personal AI key storage for individual staff accounts is not included in 1.28.0.

Publishing, settings and interface improvements

  • New Post/New Page actions retain URL-scoped identity; late saves cannot overwrite a newer editor's state. Unsaved drafts receive navigation confirmation, and autosave uses the current save callback.
  • Settings, profile and media drafts retain newer edits across delayed responses and failed saves. Newsletter Settings reports success only after an accepted save.
  • Registration has a wider responsive layout; account screens share consistent styling. Edit User has a wider dialog with grouped fields and an avatar preview.
  • Verification-email resend appears only after valid credentials require verification, not for every guest. Account-action token storage and password/reset ordering are strengthened.
  • Avatar loading and cleared-profile state are consistent across admin, profiles and comments. Guest comment tracking avatars are suppressed, and empty spam-keyword entries no longer match every comment.
  • Discussion Manager can open the published parent article even when it is outside the currently loaded article list.
  • Ad code fields resize without height-transition lag. More complex banner layouts use the existing isolated iframe rather than losing supported positioning and decorative layers; provider-script sandbox restrictions still apply.
  • Extension uninstall is explicitly non-destructive: retained configuration is restored on reinstall, and uninstalling the selected theme safely falls back to Default. It is not a factory reset.

Media, WordPress Bridge and maintenance

  • Thin-image processing keeps dimensions at a minimum of one pixel. Invalid uploads avoid creating directories; failed processing cleans up only files belonging to that upload.
  • Media storage totals use an invalidated five-minute cache, with Windows writable-folder handling and import rollback/cache corrections.
  • PHP 8.5 image handling no longer calls deprecated imagedestroy().
  • WordPress Bridge improves namespace-independent WXR reading, excerpt/tag/SEO mapping, internal links, redirects, retry checkpoints and MySQL record identity. Password-protected imports become Drafts with a warning rather than losing their privacy boundary. Unsupported WordPress/plugin features remain documented limitations.
  • SQL backups close unbuffered metadata/count cursors before further queries, preventing MySQL error 2014 while retaining row-by-row export.
  • Post, Page and WordPress import share parsed stored-HTML checks. Redirect/profile validation and direct-access guards for internal helpers are tightened.
  • The updated OTA implementation adds temporary-tree HTTP shielding and package PHP-version preflight while retaining activation and rollback behavior. Older installed updaters do not gain these protections retroactively; follow the transition guidance before updating.
  • Source development includes ESLint, PHPStan Level 9 targeting PHP 8.2, formatting/BOM checks and expanded regression coverage. Unused source modules are removed and dependencies refreshed. These development tools are not production hosting requirements.

Before upgrading

  1. Back up files and database, and test on local/staging first where possible.
  2. Use the attached Deploy ZIP for an existing or new website. The Source ZIP is for development; GitHub's automatically generated source archives are not a replacement for the built Deploy package.
  3. Use PHP 8.2.0 or newer, with PHP 8.3+ recommended. Install a supported, security-patched PHP build; updating VonCMS does not update PHP. Enable DOM for content saves, OpenSSL/AES-256-GCM for encrypted AI credentials, and the additional XML/cURL prerequisites if using WordPress Bridge.
  4. On existing sites, sign in as Primary Admin and run Database > Schema Repair to enable Calendar storage and the optional Balanced analytics storage. Uploading files alone does not activate these structures or reconstruct old analytics history.
  5. Review OTA staging-shield transition requirements. Run Repair `.htaccess` when prompted by Integrity Check; Nginx-only/OpenLiteSpeed deployments require equivalent server-side rules.
  6. If using encrypted AI credentials, back up `data/credential_master.key.php` separately from SQL, including after rotation. On Linux, restore correct ownership and 0600 permissions; a SQL backup alone cannot restore access to encrypted credentials.
  7. Check the homepage, a post, a page, Dashboard, Calendar and one saved draft after updating. Existing articles and media are not rewritten or moved in bulk.
